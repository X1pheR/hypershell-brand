# Gate N — graph renderer reassessment, independent of earlier HomeSight choice

**Status:** RESEARCH / NO ENGINE ADMITTED · **Date:** 2026-11-08 · **Scope:** S16, native unthemed UI coverage.
**Authority:** canonical `projects/hypershell-application-ui-harmonization.md`, ADR-HYP-003; HomeSight's accepted functional Map contract is the mandatory capability reference, **not** an unchangeable renderer implementation requirement.

## Corrected operator intent and prior results

- Earlier HomeSight decision **D-256 selected Cytoscape.js** for the v38 Map candidate, with a rich accepted user-interaction contract. It is **historical implementation evidence**, not an immutable architecture or a veto over a better option. Changing the engine later requires a separately proven acceptance decision; do not silently rewrite the old decision or prematurely modify HomeSight.
- React Flow `@xyflow/react` is **MIT-licensed and usable without Pro**, including in complex/large custom graphs. Pro sells ready-made advanced **examples/templates** and support. "Complex graph requires a Pro runtime license" is **incorrect**. Advanced grouping/layout capabilities may still cost development time if Pro examples are not purchased. Official source: [core/license](https://reactflow.dev/), [Pro terms](https://reactflow.dev/pro), [open vs paid examples](https://reactflow.dev/examples), [performance guidance](https://reactflow.dev/learn/advanced-use/performance).
- **Homelable** [Pouzor/homelable](https://github.com/Pouzor/homelable) is a substantial working homelab network/map application built using free React Flow (`@xyflow/react`) and **Dagre** layout. Direct source index evidence: [canvas](https://github.com/Pouzor/homelable/blob/main/frontend/src/components/canvas/CanvasContainer.tsx), [layout](https://github.com/Pouzor/homelable/blob/main/frontend/src/utils/layout.ts), [dependencies](https://github.com/Pouzor/homelable/blob/main/frontend/package.json). It implements interactive typed nodes and edges, Proxmox and Zigbee/Z-Wave imports, containers/zones, multiple canvases, real-time status, editing and export; see [features](https://homelable.net/) and [changelog](https://github.com/Pouzor/homelable/blob/main/CHANGELOG.md). This disproves that free React Flow is restricted to trivial diagrams. Homelable remains a **reference implementation, not a package to copy or a functional data owner**.
- Our retired **dev-only React Flow Storybook spike** had story-harness/CI integration failures. It is not reliable evidence that the React Flow engine cannot meet the HomeSight functional envelope. Any new experiment must be independent, cancellable, testable and scoped; no speculative Graph component published.

## Decision-changing bake-off (proposed, not executed)

**Benchmark the same actual user outcomes**, without giving the historical Cytoscape UI any automatic visual/parity advantage. Reuse HomeSight's accepted **functional** Map and inventory contract: six projection types (Overview, Deployment, Network, Logical, Ingress, Observability), semantic directed/multiple edges, truthful issue severity, Home/OCI/Internet visual zones distinct from real compound containment, selection/detail routing, pin/move/reset of browser-local view positions, deterministic re-layout, focus/keyboard controls, box selection, pan/zoom, density and semantic label legibility. Preserve actual Inventory ownership, not replicate a second data backend.

1. **Fixtures:** Synthetic, permission-free models at representative sparse/medium/dense sizes (illustrative 100/500/1500 nodes with 1×/3× edge-to-node ratios), with compounds, visually grouped *non-parent* zones, bidirectional/parallel edges, long labels and multi-projection changes. Confirm real target scale and hardware envelope from HomeSight owner before final thresholds; do not invent production volume.
2. **Separate isolated harness:** Compare React Flow (Dagre then ELK when justified), Cytoscape (fCoSE/Dagre as applicable) and AntV G6. Sigma is only added if the measured data volume makes the three candidates insufficient. No new Storybook package or backend deployment, no replacing HomeSight's active renderer. No Pro assets or access-required examples.
3. **Functional gates before beauty:** Dense link navigation, drag and constrained pin permanence, layout stability when filters/status change, correct parent/zone semantics, node identity and Inspector routing, keyboard/equivalent accessible list, pointer and emulated touch, actual 400% Chrome zoom, no unsafe HTML or remote runtime, CSP, light/dark readability.
4. **Measure, don't assume:** Use same fixture, browser, hardware and interaction script; record initial render, peak JS heap, number of interactive elements, pan/zoom and selection responsiveness, layout time, edge crossings/label obscuring, update latency after deltas, bundle size and detached/cleanup. Repeat 3 runs and report distributions rather than claiming an unsupported performance winner.
5. **Decision rule:** Prefer the smallest *number* of runtime engines meeting actual product needs. One React Flow runtime could serve both simple and complex diagrams if it passes the HomeSight benchmark; one Cytoscape or G6 engine could also suffice. Two engines need a measurable functional/user-value win outweighing dependency, testing, maintenance and accessibility cost. Selecting a future HomeSight replacement requires operator acceptance and downstream SDLC/product release gates.

## Gate boundary

This research **reopens S16 renderer selection** while keeping D-256 as a traceable historical decision until explicitly superseded. **No new graph library added, no native modules changed, no current Cytoscape removal, no theme or app migration.** Gate N remains OPEN, Gate T HARD BLOCKED, Draft PR #1 stays Draft. The earlier React Flow spike's CI failures should not be recycled as an engine-quality judgment.
