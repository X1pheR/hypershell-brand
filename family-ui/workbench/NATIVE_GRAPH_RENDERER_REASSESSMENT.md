# Gate N — graph renderer reassessment, independent of earlier HomeSight choice

**Status:** RESEARCH / NO ENGINE ADMITTED · **Date:** 2026-11-08 · **Scope:** S16, native unthemed UI coverage.
**Authority:** canonical `projects/hypershell-application-ui-harmonization.md`, ADR-HYP-003; HomeSight's accepted functional Map contract is the mandatory capability reference, **not** an unchangeable renderer implementation requirement.

## Corrected operator intent and prior results

- Earlier HomeSight decision **D-256 selected Cytoscape.js** for the v38 Map candidate, with a rich accepted user-interaction contract. It is **historical implementation evidence**, not an immutable architecture or a veto over a better option. Changing the engine later requires a separately proven acceptance decision; do not silently rewrite the old decision or prematurely modify HomeSight.
- React Flow `@xyflow/react` is **MIT-licensed and usable without Pro**, including in complex/large custom graphs. Pro sells ready-made advanced **examples/templates** and support. "Complex graph requires a Pro runtime license" is **incorrect**. Advanced grouping/layout capabilities may still cost development time if Pro examples are not purchased. Official source: [core/license](https://reactflow.dev/), [Pro terms](https://reactflow.dev/pro), [open vs paid examples](https://reactflow.dev/examples), [performance guidance](https://reactflow.dev/learn/advanced-use/performance).
- **Homelable** [Pouzor/homelable](https://github.com/Pouzor/homelable) is a substantial working homelab network/map application built using free React Flow (`@xyflow/react`) and **Dagre** layout. Direct source index evidence: [canvas](https://github.com/Pouzor/homelable/blob/main/frontend/src/components/canvas/CanvasContainer.tsx), [layout](https://github.com/Pouzor/homelable/blob/main/frontend/src/utils/layout.ts), [dependencies](https://github.com/Pouzor/homelable/blob/main/frontend/package.json). It implements interactive typed nodes and edges, Proxmox and Zigbee/Z-Wave imports, containers/zones, multiple canvases, real-time status, editing and export; see [features](https://homelable.net/) and [changelog](https://github.com/Pouzor/homelable/blob/main/CHANGELOG.md). This disproves that free React Flow is restricted to trivial diagrams. Homelable remains a **reference implementation, not a package to copy or a functional data owner**.
- Our retired **dev-only React Flow Storybook spike** had story-harness/CI integration failures. It is not reliable evidence that the React Flow engine cannot meet the HomeSight functional envelope. Any new experiment must be independent, cancellable, testable and scoped; no speculative Graph component published.

## Decision-changing bake-off (proposed, not executed)

**Benchmark the same actual user outcomes**, without giving the historical Cytoscape UI any automatic visual/parity advantage. Reuse HomeSight's accepted **functional** Map and inventory contract: six projection types (Overview, Deployment, Network, Logical, Ingress, Observability), semantic directed/multiple edges, truthful issue severity, Home/OCI/Internet visual zones distinct from real compound containment, selection/detail routing, pin/move/reset of browser-local view positions, deterministic re-layout, focus/keyboard controls, box selection, pan/zoom, density and semantic label legibility. Preserve actual Inventory ownership, not replicate a second data backend.

1. **Fixtures:** Synthetic, permission-free models at representative sparse/medium/dense sizes (illustrative 100/500/1500 nodes with 1×/3× edge-to-node ratios), with compounds, visually grouped *non-parent* zones, bidirectional/parallel edges, long labels and multi-projection changes. Confirm real target scale and hardware envelope from HomeSight owner before final thresholds; do not invent production volume.
2. **Separate isolated harness:** Compare React Flow (Dagre then ELK when justified), Cytoscape (fCoSE/Dagre as applicable) and AntV G6. Sigma is only added if the measured data volume makes the three candidates insufficient. No new Storybook package or backend deployment, no replacing HomeSight's active renderer. No Pro assets or access-required examples.
3. **Functional gates before beauty:** Dense link navigation, drag and constrained pin permanence, layout stability when filters/status change, correct parent/zone semantics, node identity and Inspector routing, keyboard/equivalent accessible list, pointer and emulated touch, actual 400% Chrome zoom, no unsafe HTML or remote runtime, CSP, light/dark readability.
4. **Measure, don't assume:** Use same fixture, browser, hardware and interaction script; record initial render, peak JS heap, number of interactive elements, pan/zoom and selection responsiveness, layout time, edge crossings/label obscuring, update latency after deltas, bundle size and detached/cleanup. Repeat 3 runs and report distributions rather than claiming an unsupported performance winner.
5. **Decision rule:** Prefer the smallest *number* of runtime engines meeting actual product needs. One React Flow runtime could serve both simple and complex diagrams if it passes the HomeSight benchmark; one Cytoscape or G6 engine could also suffice. Two engines need a measurable functional/user-value win outweighing dependency, testing, maintenance and accessibility cost. Selecting a future HomeSight replacement requires operator acceptance and downstream SDLC/product release gates.

## Executed neutral benchmark — 2026-11-09 (measured, **not** renderer admission)

**Reproducible source and raw samples:** [isolated 2026-11-09 research workspace](research/s16-graph-bakeoff-20261109/README.md), including exact pinned `package-lock.json`, source fixtures, isolated Playwright harness and raw JSON `reports/full.json`, `reports/acceptance.json`. Temporary OCI execution workspace `/srv/hypershell/tmp/graph-bakeoff-s16-20261109/` was used; **no external UI endpoint, production HomeSight or official native module was altered**. Engine pins: `@xyflow/react@12.12.1`, `cytoscape@3.34.4`, `@antv/g6@5.1.1`, `@dagrejs/dagre@1.1.8`; verified all four are MIT. Common synthetic fixture (100, 500, and stress-only 1,500 nodes, 3 directed edges/node, labels/status/site metadata) and equal preset graph positions. Synthetic status update modifies 50 nodes, plus select, viewport pan and **preset position replacement**. These do **not** yet prove native group/compound behavior, force/Dagre/ELK layout or real inspector/Graph action parity.

**Execution:** 3 repetitions × 3 engines × 3 scales = **27/27 pass** without throttle (`run-20261109T071902386155Z-04da10a676a9`). Separately the actual HomeSight boundary fixture 100/300 and 500/1500 was measured with one warm-up and five observed samples per engine, CDP **4× CPU throttle**, **20 Mbit/s**, **40ms latency**: **36/36 pass** including six warmups (`run-20261109T072139118920Z-fd4cabda724f`). Browser: isolated ARM64 headless Chromium on OCI, Chrome context per sample, local loopback-only static bundles; performance timings include HTTP and module loading and are **comparative only** (static files uncompressed, product integration/CSP/long labels/icons/true containment and realistic staged-data behavior absent). Median and max values are measured, not hypotheses.

| Profile, median of five measured | Cytoscape.js | React Flow | AntV G6 |
| --- | ---: | ---: | ---: |
| 100 nodes / 300 edges: first ready | **1,537 ms** | **1,244 ms** | 2,689 ms |
| 100/300: max first ready | 1,742 ms | 1,328 ms | 2,910 ms |
| 100/300: node select | 86 ms | **30 ms** | 109 ms |
| 100/300: update 50 statuses | **85 ms** | 439 ms | 319 ms |
| 100/300: JS heap after first ready | 9.4 MiB | **8.4 MiB** | 14.4 MiB |
| 500 nodes / 1,500 edges: first ready | **2,796 ms** | 3,010 ms | 5,386 ms |
| 500/1500: select | **271 ms** | 415 ms | 433 ms |
| 500/1500: update 50 statuses | **281 ms** | 1,905 ms | 616 ms |
| 500/1500: JS heap after first ready | **18.7 MiB** | 25.1 MiB | 61.0 MiB |

**Important interpretation:** At the 100/300 rich Map boundary, both simple React Flow and Cytoscape prototypes meet the existing **2,000 ms initial-ready target in this isolated profile**; G6 does not. At 500/1500, current naive React Flow updates are much slower and its DOM contains 500 node elements and 1,500 SVG edge elements. These numbers are **not production acceptance**: the accepted HomeSight rich Map also needs 22 TRB hard requirements, complex labels/icons, nested real containment, separately visual-only Home/OCI/Internet zones, six projection layouts, persistent pins, canonical inspector/edges, accessibility and safe dense rendering. A React Flow optimization (memoized custom node/edge components, state boundaries and density staging) must precede a disqualification; equally the current lightweight G6 prototype **does not replicate** the earlier comprehensive G6 adapter that was measured substantially slower. See `topology-renderer-bakeoff-evidence.md` in the HomeSight canonical owner for the earlier accepted Cytoscape/G6/Sigma behavior, and the approved `ui-performance-contract.md` for thresholds.

**Stress-only, outside automatic HomeSight rendering policy:** at 1,500 nodes / 4,500 relationships all **9/9** unthrottled runs passed; median ready Cytoscape **1,318 ms**, React Flow **1,978 ms**, G6 **2,572 ms**; 50-node update Cytoscape **176 ms**, React Flow **1,338 ms**, G6 **286 ms**. The HomeSight TRB-H19 guard forbids unconditional full-graph rendering above **1,000 nodes or 3,000 relationships**: the stress fixture measures engine overhead, **not** an acceptable app feature.

**Genuine browser 400% tab zoom** (isolated Chrome extension `chrome.tabs.setZoom=4`, observed `innerWidth=320`, DPR4; `run-20261109T072727784061Z-90b470e64a16`): 100/300 cases across all three engines have **0 page horizontal overflow**, no JavaScript errors; synthetic user-interface `Select first` tap via Chromium touch emulation updates `n0`. An initial Cytoscape screen's 7px overflow was traced specifically to one overly wide **experiment header button**, corrected without changing any graph engine. **Not proven:** actual hardware touch, graph node/edge canvas hit testing, keyboard traversal or 400%-zoom usability at dense real data. The direct graph DOM contained **400 tab-focusable elements** for React Flow at 100/300, versus **0** Cytoscape and **4** G6 (mixed graph/controls); none of those raw counts proves accessible end-user navigation. Excessive tab stops and missing canvas node semantics are **different risks** requiring a shared accessible list/Inspector UX.

**Isolated dependency chunks, gzip -9** (not a complete app route): React Flow 59,211 B (plus 2,536 B CSS), Cytoscape 136,784 B, G6 397,576 B; common Vite/React shell has separate shared chunks. The accepted topology route is capped at **900 KiB gzip** total; these standalone chunk sizes cannot establish whole-product transfer compliance.

**Outcome: research progressed, not accepted.** No engine rejected or selected. React Flow is **feasible without Pro** at real 100-node graph scale and Homelable is an external validation of functional ambition. Cytoscape currently has the strongest **measured dense-update signal** and a much more complete historical HomeSight feature proof. G6 remains technically viable but has more load/heap and a prior functional-complexity cost. **Next autonomous slice:** port the same previously accepted HomeSight group/zone, route/relationship selection and pin-update fixture to React Flow (and retain equivalent existing Cytoscape/G6 functional evidence); evaluate actual keyboard/hardware equivalent fallback and 400%-zoom, then decide on one-engine convergence or justified specialist split. Gate N OPEN, Gate T HARD BLOCKED, Draft PR unchanged except research docs/source.

## 2026-11-10 continuation after CS-027: optimized React Flow and rich functional proof

**ChatGPT interruption did not roll back work.** The native benchmark [Reach Run `run-20261109T073951668790Z-a7858522db96`](https://reach.hypershell.eu/runs/run-20261109T073951668790Z-a7858522db96) ended `succeeded` with exit `0` on 2026-11-09; the complete `reports/optimized.json` file survived intact. The separate operator-reported UI stall is recorded as **CS-027** in private Vault OpenAI support tracking, not an OCI or graph renderer failure.

**Reproducible source and raw samples:** [isolated benchmark research directory](research/s16-graph-bakeoff-20261109/README.md). The previously omitted React Flow optimization is decisive: against the **same 4× CPU, 20 Mbit/s, 40ms RTT, one warmup + five measured samples** profile, the plain 500-node React Flow adapter had median **2,049 ms** for updating 50 statuses and **3,027 ms** to first ready; the stable `memo` custom-node adapter reduced this to **104.4 ms** and **1,664 ms** respectively. At 100/300 it reduced update from **481 ms to 73.5 ms**, first ready from **1,344 to 1,015 ms**. All **24/24** browser runs passed. This demonstrates that the earlier naive React Flow slow-update signal was highly sensitive to adapter design; **do not reject React Flow on the unoptimized results**. It does **not** prove universal engine superiority, since Cytoscape and G6 were not optimized to exactly the same UI workload.

**Combined richer functional proof:** On 2026-11-10 a new free React Flow wrapper passed **12/12** isolated Playwright runs under the same throttled profile (one warmup, five measurements per 100/300 and 500/1500), [Reach Run `run-20261110T060410334940Z-4a5038897fed`](https://reach.hypershell.eu/runs/run-20261110T060410334940Z-4a5038897fed). Synthetic, not product data. It combines two nested real parent groups, three independent decorative Home/OCI/Internet zones, semantic directed edges, node/relationship selection, searchable keyboard-accessible inspector, browser-local per-projection pinning, retaining pin coordinates during preset re-layout, current-projection-only reset, six selectable projection tabs and responsive 320px page reflow (no horizontal overflow).

| Optimized rich adapter, median of five 4×-CPU runs | 100 nodes / 300 relationships | 500 nodes / 1,500 relationships |
| --- | ---: | ---: |
| Initial ready | **1,105 ms** | 2,187 ms |
| Inspector selection (browser automation included) | **238 ms** | 382 ms |
| 50 status updates (browser automation included) | 123 ms | 397 ms |
| Initial JS heap | 7.9 MiB | 28.7 MiB |

**Remaining evidence gaps:** This is proof of **capability**, not complete HomeSight semantics or release acceptance. The fixture does **not** run Dagre/ELK/fCoSE automatic layouts, real multi-projection graph queries, canonical Inventory/Relationship integrity, route-first inspector wiring, full drawn site packing or staged oversize guards. The richcase selection path's observed 238ms exceeds the 200ms HomeSight selection goal in this harness, but includes Playwright click/wait overhead; a product-level timing method is required before adjudicating. The 100/500 rich scene passed **320px viewport resize**, not genuine 400% Chrome zoom; genuine Chrome 400% + emulated touch were previously verified for the **small eight-node rich** fixture. Physical hardware touch and keyboard/graph accessibility equivalence remain unverified.

**Decision:** React Flow core MIT is now **strongly viable** as a configurable implementation for both simple graphs and rich topology, with meaningful non-Pro compound/pin/projection research. Cytoscape retains its existing comprehensive HomeSight contract evidence and stronger initial dense-update efficiency in the unoptimized comparison. G6 has measured scope/performance trade-offs. **No renderer winner or adoption of two engines is proven.** For the next decision-changing step, compare optimized full HomeSight interactions, stable automatic layout with pins, real product inspector/keyboard semantics and change-under-load on a representative browser. Keep current HomeSight renderer and native Family UI source unchanged; Gate N OPEN, Gate T HARD BLOCKED.

## 2026-11-10 — real automatic layouts, native pin constraints and historical HomeSight profile sizes

**Observed, research-only:** the independent [S16 layout source and raw report](research/s16-graph-bakeoff-20261109/README.md) now runs **actual** Dagre compound, ELK Layered nested and Cytoscape fCoSE compound algorithms on synthetic 22/29 and 60/77 Items/Relationships, with two added Items and three edges and two pinned anchors. The sizes and change shape are aligned to the earlier accepted HomeSight [Topology Renderer Bake-off Evidence](https://ignis.hypershell.eu/?vault=hypershell&file=projects%2Fhomesight-canonical-inventory-model%2Fhomesight-docs%2Ftopology-renderer-bakeoff-evidence.md), but **the data/edge topology are not the same**, so numeric metrics must not be directly equated.

| Same synthetic profile, median of three executions | Dagre | ELK Layered | Cytoscape fCoSE |
| --- | ---: | ---: | ---: |
| 22/29: initial layout / incremental layout | 215 / 187 ms | 76 / 63 ms | **31 / 12 ms** |
| 22/29: unchanged unpinned median displacement | 1,695 px | 129 px | **0 px** |
| 60/77: initial layout / incremental layout | 773 / 616 ms | 119 / 116 ms | **41 / 28 ms** |
| 60/77: unchanged unpinned median displacement | 2,885 px | 496 px | **0 px** |
| 60/77: maximum pinned movement **before** any adapter override | 2,759 px | 767 px | **0 px** |

**18/18 algorithm runs passed** with complete returned node identities, intact tested containment geometry and the two final pin coordinates. However, **Dagre and ELK only report 0 px final pinned drift because our experiment forcibly overrides the computed positions**; they do *not* demonstrate an equivalent native immutable-pin contract. That override can invalidate route geometry and has to be reconciled with obstacle avoidance. fCoSE `fixedNodeConstraint` preserves positions *in the algorithm* without that workaround. The 100/300 cyclic stress experiment was also executed in an earlier prototype and showed potentially expensive Dagre operations and overlap problems for the default fCoSE layout; no broad engine performance verdict follows.

**Licensing decision:** the tested `elkjs@0.12.1` license is **EPL-2.0 OR GPL-3.0-or-later** (not MIT). `@dagrejs/dagre`, `cytoscape`, `cytoscape-fcose` and `@xyflow/react` are MIT. Actual ELK redistribution requires the ordinary dependency/license gate; no ELK runtime adoption approved.

**Current S16 recommendation, explicitly provisional:** fCoSE is the **strongest evidenced layout option** for HomeSight's interactive *pinned* network topology in these tested profiles. This **does not require keeping Cytoscape as the future view layer** and does not establish React Flow as the sole preferred renderer: a React Flow view with a separate graph-layout engine is a possibility only if it yields sufficient measurable user benefit to justify the combined packages, semantics bridge and maintenance. Dagre remains a credible option for simpler directional DAGs, and ELK for layouts with ports and orthogonal routing, but their native pinned-mental-map behavior is not established by this test. Do not adopt two engines by default. Historical HomeSight D-256 stays a traceable choice, not an immutable future selection. Gate N **OPEN**, Gate T **HARD BLOCKED**, Draft PR research only; HomeSight production is unchanged.

## 2026-11-10 — rich React Flow: actual 400%-zoom and measured inspector reaction

**Measured follow-up, not full acceptance:** using the existing 100/300 and 500/1500 synthetic rich React Flow fixtures, an isolated Chromium session applied **actual tab zoom 4×** (`chrome.tabs.setZoom`, observed 320 CSS px and DPR4), **4× CPU emulation**, and **synthetic touch**. Both sizes had no page horizontal overflow, visible graph/inspector, correct status and pinned `n0`, and zero uncaught browser errors: [source and raw ten event observations](research/s16-graph-bakeoff-20261109/README.md), [Reach Run](https://reach.hypershell.eu/runs/run-20261110T085644391927Z-4ada619b5498). The fixture still lacks real canonical HomeSight data, full keyboard/graph accessibility, physical touchscreen and deployed CSP behavior, and it does not invoke the new real auto-layout solver on every interaction. **Native S16 and Gate N do not receive a GO from these results.**

## 2026-11-10 — contract-mapped S16 functional gap audit (after CS-028)

**Authority:** approved HomeSight `topology-ui-contract.md` (v40 review, accepted Map user behavior) and `ui-performance-contract.md` (last reviewed 2026-08-12) versus actual isolated `src/richscale.jsx`, `bench-richscale-zoom.cjs`, real layout algorithms and raw reports. **Historical Cytoscape D-256 is product evidence, not a mandatory future renderer selection.** The audit compares user-facing capabilities rather than naming a preferred engine from the outset.

The strongest proven incremental capability is **free React Flow rich-node composability**; the strongest verified dynamic topology layout property remains **fCoSE native pin constraints**. Compare perceived UX and complete route costs with the existing Cytoscape design using the same fixture and hardware. Only then propose a renderer decision for operator approval; Gate N remains **OPEN**, Gate T **HARD BLOCKED**, Draft PR stays Draft.
