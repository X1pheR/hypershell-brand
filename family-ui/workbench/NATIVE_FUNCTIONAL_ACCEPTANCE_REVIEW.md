## Admission rule

An app's current custom widget is never the target. First capture the user outcome, decide among official shadcn/Base UI primitive composition/official blocks, or demonstrate why a specialist product-owned adapter is required. A working Storybook research story qualifies a **native composition example**, not product-specific permissions, data semantics, backend state or real task actions. Only repeated multi-product functional evidence justifies promoting a shared wrapper. No original `src/components/ui` source patches, legacy visual parity or Hypershell-theme changes are part of this gate.

## Official source / block scope

- 63/63 official shadcn Base Nova/Base UI native modules and their story docs are represented unchanged. **Data Table, Date Picker and Typography are composite guides** in the official navigation, not three missing TSX files.
- Official dashboard/sidebar blocks already compose upstream Sidebar, Breadcrumb, Card and charts. Our research uses those official primitives and checks their behavior without wholesale transplantation of block layouts. Login/signup blocks are not automatically needed because the Hypershell authentication owner is Pocket ID.
- Markdown is a parser and document capability, **not** a native shadcn component; graph editors are specialist engines, not missing native primitives. They require explicit package version/license/CSP/security and workflow acceptance.
- The five original synthetic app pages and their 20 approved goldens remain unchanged; Storybook research additions extend the **pattern gallery**, not the application-route count. A new full-page app-route set requires separately accepted visuals and routes.

## Explicit product-ownership decisions proposed for Gate N

Do **not** build shared implementations of authentication/Pocket ID, Task/Run persistence, health metric data, alert escalation, calendar/cron scheduling, file transport, topology engine, product-specific data tables/column configurations, approvals/rollback logic, a universal rich Markdown editor, or a universal SideInspector. Use native UI components in each consuming product and specialist adapters only if a real product requirement exists.

A second complete six-case probe `run-20261108T190652038273Z-e2ccc9f813f8` passed navigation, record selection/table, searchable Help, long logs, Markdown editor/preview and record Sheet with zero top-level overflow and no unhandled browser errors. A separate exploratory sequence that tapped the Sidebar open and immediately sent Escape did **not** deterministically dismiss the Sheet, including when targeting an internal navigation control. This is an unresolved mixed-input/Storybook-runner interaction and **not proof** of a native component defect. ### 2026-11-08 S25 mixed-input Escape root cause and scoped correction

**Controlled isolation:** With the original mobile Storybook `tooltip={page}` on every `SidebarMenuButton`, the same isolated Chrome session left the native Sheet open after **one** Escape whether opened by **click or tap**, and whether zoom was **100% or true 400%** (`run-20261108T192819618231Z-1a287b5b526f`). A no-touch/no-extension/320px control reproduced it (`run-20261108T192900051688Z-454077e8ad91`). The keydown event itself arrived at the focused Sidebar menu button (`run-20261108T192718377212Z-2de3054da029`). A subsequent controlled press sequence observed **multiple `data-open` overlay layers drop on the first Escape, then the Sheet close and focus return on the second** (`run-20261108T193026794723Z-227c5eb00496`). The evidence contradicts a zoom-only or physical-touch-only defect.

**Minimal fixture fix:** The neutral Storybook navigation story renders full-text menu labels inside the mobile Sheet, so tooltip layers add no benefit there. A small `PageMenuButton` child reads native `useSidebar().isMobile` and passes `tooltip={isMobile ? undefined : page}`, preserving existing desktop tooltip behavior and **not patching official native Sidebar/Tooltip**. The permanent true 400% zoom regression now verifies **one Escape following an emulated touch tap** closes the Sheet and restores focus to `Toggle navigation`. Two independent isolated runs succeeded with all six original 400%-zoom workflows (`run-20261108T193243737522Z-908a00128b8d`, `run-20261108T193326427857Z-df1ce8b0c5f7`). The 320/390px Storybook keyboard CI and all original visual goldens remain required; the corrected source must still pass exact GitHub CI. This resolves the *neutral Storybook fixture mixed-input* blocker, **not physical device certification**.
